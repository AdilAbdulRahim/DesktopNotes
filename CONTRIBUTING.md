# Contributing to DesktopNotes

Thanks for your interest in contributing! We welcome issues, pull requests and ideas.

How to contribute
- Search existing issues before opening a new one.
- For bugs: open an issue with steps to reproduce and attach logs/screenshots.
- For new features: open a feature request and describe the use-case.
- To contribute code: fork the repository, create a feature branch, make small commits, and open a pull request against `main`.

Pull request checklist
- [ ] The PR targets the `main` branch
- [ ] Builds cleanly (`dotnet build DesktopNotes.sln -c Release`)
- [ ] No obvious performance regressions
- [ ] Tests (if present) pass
- [ ] Include a concise description of the change and motivation

Coding style
- Follow existing project conventions (C# naming, file layout).
- Keep changes focused and small; split large changes into multiple PRs.

Communication
- Use GitHub discussions or issues for design-level conversations.

Security
- Do not open a public issue for security vulnerabilities. See SECURITY.md for private reporting.

Thank you for helping make DesktopNotes better!
